# DY Live Assistant · 抖音直播间助手

面向 Windows 的桌面助手，提供 **秒杀下单** 和 **批量下单** 两个模块，支持指定商品匹配、多规格选择、金额核对及自动点击支付。

本仓库以 Python 桌面版为主要入口，保留 Node.js Web / CLI 代码供开发和学习使用。两个实现的功能不完全一致，本文的主要功能说明以桌面版为准。

> 默认开启“只测试，不下单（DRY_RUN）”。真实运行可能产生订单和扣款；软件不保证抢购成功，也不会绕过实名、支付密码、验证码、扫码或平台风控。

## 核心功能

### 网络检测

右侧“网络检测”页签可测试抖音直播站点与 Cloudflare 的 HTTPS 首包延迟、响应抖动、请求失败率及单连接下载吞吐（Mbps / MB/s）。下载样本最多 8 MiB，慢连接达到时间上限后按已接收数据估算。检测在后台运行，可停止；监控、批量下单、登录任务与测速互斥，避免占用抢购网络。

“较好 / 一般 / 较差 / 无法评估”是站点连接的经验评价，不是抢购成功概率。HTTPS 首包包含连接与服务器处理，非 ICMP ping；失败率不是丢包率。直连检测与浏览器代理线路可能不同，Cloudflare 吞吐也不代表抖音下单接口表现。站点 HTTP 异常或样本不足时不推断成功率。

### 秒杀下单：提前等开卖

默认开启“极速购买”：等待阶段确认目标商品并绑定唯一购买控件，检测开售后直接原生点击，不再读商品名称或搜索购买按钮。商品卡片被整体替换时仍需重新绑定；无法提前绑定唯一控件时使用原有路径。原生点击保留浏览器的可点击检查，结算及自动支付开关不变。点击失败会记录底层原因并按诊断设置保存快照；不盲目重复点击，避免重复订单。此优化不保证真实库存或抢购成功。

可选“实验极速模式”，默认关闭，开启后独立启用提前绑定，只对该绑定购买控件触发页面脚本点击，省去原生点击的稳定性等待。派发前在页面内重新检查绑定控件可购买、未禁用、在线且未超过监控期限。脚本点击是非受信任事件，平台可能忽略；结果不明不会自动补一次原生购买点击。支付仍使用原生点击并保留金额核对；批量下单及无法提前绑定的路径不改为脚本点击。日志的“已触发页面购买事件”不代表订单成功；未获结算确认时停止并提示关闭实验模式。

填写直播间、目标商品、价格和规格后，可以提前启动：

- 在直播间商品列表中寻找目标商品。
- 商品尚未开售时锁定目标卡片，监听按钮和状态变化。
- 识别到开放购买后重新核对商品，进入下单流程。
- 支持即时监控和最多四个每日监控区间，每段最长一小时，支持跨午夜。
- 商品初始已抢光时等待上架；本轮开售后售罄，可选择继续监控补库存或停止，结果日志按状态变化去重。
- 普通秒杀结算使用已验证的主支付控件快路径，减少重复全页扫描；结算页库存耗尽与金额不符分别处理，仍保留点击前金额和可用状态校验。
- 结算金额和按钮变化会立即唤醒检查；商品卡片被替换时重新核对身份和唯一性后就地恢复监听。原生点击仍检查遮挡、可用状态和稳定性，不使用强制点击。
- 收到支付成功提示后，日志汇总打开链接、检测开售、购买点击、提交到成功确认的毫秒耗时；进入结算页或仅点击支付不等于成功。

监听的是浏览器已收到的页面变化，不能提前获取服务器库存，也不保证绝对第一时间抢到商品。

### 批量下单：减少重复操作

填写同一商品的详情链接，设置“买几单、每单几件”：

- 每单重新打开商品链接。
- 按配置选择规格、设置数量并核对金额。
- 开启自动支付时，确认当前单出现成功提示后才继续下一单。
- 规格、数量、金额或支付结果不明确时停止后续操作。

这是同一商品、同一规格组合的顺序购买，不是多个不同商品混合下单，也不是并发下单。

### 配套能力

| 功能 | 作用 |
| --- | --- |
| 多规格选择 | 预填颜色、尺寸、款式、补价等选项，确认选中后继续 |
| 严格金额核对 | 支付前再次核对；批量按单价 × 每单数量检查，一分钱差异也停止 |
| 只测试不下单 | 先检查商品匹配和购买入口，不创建订单 |
| 登录资料保存 | 专用浏览器保存登录会话，两个模块共用 |
| 支付结果保护 | 支付点击不重试；结果不明确时停止并保留页面供核对 |
| 中文界面与日志 | 区分任务、下单方式、规格和高级参数，显示进度与停止原因 |

## 普通用户怎么用

详细操作请先阅读 [用户使用说明](用户使用说明.md)。

### 使用已经打包的 Windows 软件

前往 [GitHub Releases 下载 Windows 发行版](https://github.com/Tyler-Xixi/dy-live/releases/latest)，或直接下载 [完整 Windows ZIP 包](https://github.com/Tyler-Xixi/dy-live/releases/download/v2026.10.07/DYLiveAssistant-Windows-2026.10.07.zip)。下载后先解压，再启动软件。

完整 ZIP 包包含 EXE、运行依赖和用户手册。发行页也提供单独的 EXE，但它不能脱离 `_internal` 文件夹独立运行，普通用户请下载完整 ZIP。真实卡密不公开上传，需向管理员取得。

```text
DYLiveAssistant/
├── DYLiveAssistant.exe
├── _internal/
└── 用户使用说明.md
```

1. 保留整个文件夹，双击 EXE。不要只复制 EXE 或删除 `_internal`。
2. 首次启动按提示输入管理员提供的卡密。
3. 点击“登录抖音”，在专用浏览器中完成官方登录，再点击“完成登录并保存”。
4. 选择“日常秒杀监控”或“批量下单”，填写商品信息。
5. 保持测试模式开启，检查匹配到的商品是否正确。
6. 确认账号、商品、规格、价格、数量和地址后，才关闭测试模式。
7. 需要自动支付时开启“进入结算页后自动点击支付”，阅读确认框后启动。

目标电脑需要安装 Microsoft Edge 或 Google Chrome；使用发行版不需要自行安装 Python 或 Node.js。

### 价格与规格怎么填

- 秒杀模式：目标金额填准确的购买金额，不是最高预算。
- 批量模式：目标单价填每件价格，程序用单价乘每单数量核对总额。
- 商品编号：直播间列表序号，不是商品名称中的数字或规格。
- 多规格：推荐填写 `规格组=选项名称`，不同组用 `|` 分隔。
- 每个需要选择的规格组都应填写一个选项，不能在同一组同时指定多个值。

```text
单个规格组：补价=12
多个规格组：颜色=粉色 | 尺寸=大号

批量示例：
目标单价 12 元，订单数 3，每单数量 2
每单预期金额 24 元，共 3 单、6 件
```

邮费、优惠或规格变化可能使结算额与配置不符；请先检查实际费用，不要直接关闭金额核对。

### 支付成功怎样判断

“点击购买”“到达结算页”“已点击立即支付”都不等于扣款成功。

自动支付流程最多等待约 15 秒识别页面“支付成功”或“订单支付成功”提示。没有确认时停止后续动作；这不代表一定失败或一定未扣款，应先查抖音订单和支付账单，避免重复购买。

如果需要密码、验证码、扫码或人脸验证，由账号本人在官方页面处理。点击“停止任务”不会撤销已创建订单或已处理的支付。

## 开发者快速开始

### 环境

- Windows。
- Python 3.10 或更高版本，并能够使用 Tkinter。
- 桌面版浏览器测试需要 Microsoft Edge。
- Node.js / npm 仅用于保留的 Web / CLI 实现。

### 获取源码和安装依赖

```powershell
git clone https://github.com/Tyler-Xixi/dy-live.git
cd dy-live
python -m pip install -r requirements-build.txt
```

依赖版本以 `requirements-python.txt` 和 `requirements-build.txt` 为准。

### 本地生成自己的激活卡密

公开源码不含 `local_license_keys.py`、卡密 CSV 或卡密数据库。缺少卡密校验模块时激活不会放行，管理员应先生成自己的数据：

```powershell
python card_admin/generate_cards.py --count 100
python card_admin/export_local_keys.py
```

首次生成后，本地会得到：

- `card_admin/generated_cards.csv`：卡密明文，管理员保管。
- `card_admin/cards.db`：卡密哈希数据库。
- `local_license_keys.py`：客户端本地校验模块。

**以上文件不要提交到公开仓库。** 生成脚本拒绝覆盖已有导出 CSV；补充新卡密请阅读 [卡密管理说明](card_admin/README.md)，不要覆盖、混用或丢失既有卡密。

旧版离线激活仍为本地校验，同一卡密可能在不同电脑分别激活，不受网站远程管理。本地 CSV 发放状态需管理员自行记录。

### 联网激活与管理员网站

新增独立 `license_server/` 授权服务，提供单管理员中文卡密管理、天数/永久期限、首次激活绑定电脑、续期、停用、解绑和归档。完整新卡密只在生成响应中显示一次，数据库不保存明文。部署步骤见 [授权服务部署说明](license_server/deploy/README.md)。

客户端可明确选择“联网卡密”或“旧版离线卡密”，两种记录隔离，不因网络失败自动切换。已成功联网激活的有效凭证允许不限时断网使用，但自身期限仍到期；停用/解绑须下次成功联网才能传达，长期离线旧机可能继续运行。机器指纹与客户端检查不是不可破解的 DRM。

联网验证在后台进行，购买路径只读内存授权快照；失效阻止新购买并保留浏览器，不关闭人工验证页或中断已提交订单的只读确认。2026-10-09 已完成正式部署，`license_config.py` 固定实际服务器公钥，dist发行已通过公网激活与启动验收。管理员网站：https://license.txblog.cn/admin 。

### 运行桌面版

```powershell
python dy_grab_gui.py
```

首次运行仍需使用自己生成的卡密激活，然后进行官方账号登录。

也可运行 `启动PythonGUI.bat`；该脚本会检查依赖并尝试安装 Playwright Chromium，需要网络。专用浏览器优先使用已安装的 Edge / Chrome。

### 测试

```powershell
python -B -m unittest discover -s tests -v
npm run check
```

回归测试覆盖商品匹配、等待开售及补库存、跨午夜监控、多规格、数量与金额校验、图片遮罩、重复支付保护和本地激活等场景。

浏览器测试使用本地模拟页面与无头 Edge；卡密测试使用虚拟测试数据，不依赖管理员真实 CSV，不创建真实订单。测试通过不等于已经验证某个直播间能够实际扣款。

端到端库存竞争模拟：

```powershell
python tests/flash_sandbox.py --trials 5 --report build/realistic-sandbox.json
python tests/flash_sandbox.py --trials 2 --scenarios price_changed,uncertain,verification --report build/realistic-sandbox-safety.json
```

模拟服务仅绑定本机地址，临时浏览器上下文只允许其确切端口；不读取真实账号资料。商家按独立时钟上架，其他买家按时间表消耗库存，服务端原子判断订单；覆盖推送延迟、结算加载、金额异步更新、卡片替换、遮罩、库存耗尽、响应丢失和支付验证。它模拟可观察行为，不复刻抖音内部协议、风控或实际抢购成功率。`--compare --baseline build/before-realistic-sandbox.exe` 可对保留的本次优化前 EXE 内嵌下单逻辑做相同参数的交替对比；需要 PyInstaller 读取基准，性能测试请串行运行。

### 打包 Windows EXE

在本地生成自己的卡密校验模块并安装构建依赖后执行：

```powershell
python -m PyInstaller --noconfirm --clean dy_live.spec
Copy-Item -LiteralPath "用户使用说明.md" -Destination "dist/DYLiveAssistant/用户使用说明.md" -Force
```

也可使用 `构建EXE.bat`。输出在 `dist/DYLiveAssistant`，请分发完整文件夹。

发行包中不要夹带卡密管理目录、个人浏览器资料或诊断记录。

### 详情页锁单（可选）

在日常秒杀中勾选“详情页锁单”，使用完整商品名称、编号、目标金额。此模式独立于“自动点击支付”和实验页面事件：提前点击已确认商品的标题进入详情，等待可用的网页支付控件，核对一件商品及金额后原生点击一次。仅发现二维码不算可下单；看到新的订单号和待付款状态才确认锁单，随后保留浏览器，不继续付款、不执行放弃支付。

若已确认的商品列表出现开售信号，而详情仍是二维码或售罄页，立即安全重开一次详情；其它等待状态默认每2000毫秒尝试通过唯一安全返回入口重新打开，定时间隔最低500毫秒。没有安全入口时仅持续监听并提示，不强制刷新直播间。重新打开是否实际更新库存取决于平台缓存和页面实现，尚未通过真实补库存事件验证。若页面只支持App购买，此模式不能创造网页购买入口。

检测到可见验证码／人机验证时，详情页锁单自动暂停刷新与点击并保留浏览器，日志显示“监控暂停，等待人工验证”。本人完成验证且正确商品详情恢复后自动继续，原监控区间不延长；已提交的订单只继续核对结果，绝不重新提交。区间结束时仍保留验证页面，点击“停止”或关闭软件会释放浏览器。程序不会解验证码或绕过验证；未识别的新布局仍需提供脱敏诊断。

关闭“只测试，不下单”才会真实提交。虽然模式不继续后续付款，首次点击“支付”是否扣款仍取决于平台及账号设置，不能保证仅锁库存。提交结果不明确时停止并保留页面，勿直接再次启动。日志区分“已点击提交”和“待付款订单已确认”，提供检测可提交→点击、点击→待付款确认的毫秒耗时；打开链接总耗时包含等待商家开售。

## 数据与隐私

EXE 运行数据默认位于 `%LOCALAPPDATA%/DYLiveAssistant`。源码运行或自定义资料目录时，路径以配置为准。

浏览器资料可能包含登录会话；截图、HTML 和网络响应可能包含账号、收货地址或订单信息。反馈问题时只提供必要且已脱敏的资料，不发送卡密、验证码、密码、会话令牌或完整登录目录。

本次整理从 `main` 当前版本移除了旧登录资料、诊断记录与网络压缩包。**普通删除提交不会清除历史中的旧内容。** 若历史内容包含有效登录会话或其他秘密，应停止共享这些资料、检查并撤销相关会话；彻底处理历史暴露需要单独评估，不能把文件删除视为秘密已经失效。
