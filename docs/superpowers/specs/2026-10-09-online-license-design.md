# 联网激活与卡密管理网站设计

日期：2026-10-09  
状态：用户于 2026-10-09 确认本书面设计；书面实施计划待审阅，尚未开始实施。

## 1. 目标与既有环境

为 DYLiveAssistant 新增联网一卡一机激活与单管理员卡密管理网站，保留旧版通用离线卡密及已有激活记录。授权检查不得进入商品开售到点击下单的关键路径，不改变现有秒杀、批量下单、人工验证暂停恢复逻辑。最终客户端交付位于 dist/DYLiveAssistant/DYLiveAssistant.exe。

服务器由用户通过 Xshell 管理：腾讯云 Ubuntu 24.04，公网 IP 119.45.132.220。阿里云负责 txblog.cn 的 DNS；license.txblog.cn 的 A 记录已添加，本机查询指向该 IP。

现有 blog-frontend 使用 nginx:alpine，发布宿主机 80 端口；博客后端、MySQL、Redis 和 openclaw 是既有独立容器。此前只读检查未发现 443 监听，但上线前须再次确认。不读取博客数据库、用户账号、SSH 私钥或旧版卡密明文文件，不覆盖博客服务。

## 2. 范围与重要边界

- 管理地址：https://license.txblog.cn/admin；授权 API 与管理网站同源。
- 一个管理员，账号密码登录；无公开注册、用户中心、在线支付、分销或多管理员权限系统。
- 管理网站只控制新联网卡密。旧版离线卡密继续原逻辑，不受远程停用、期限编辑或设备解绑控制。
- 联网验证失败不自动转换成旧版离线激活；用户必须明确选择入口并持有该入口的有效凭证。
- 已成功联网激活且凭证有效的电脑，在网络故障时无额外宽限时限；卡密自身到期时间仍有效。
- 无限断网宽限意味着停用、缩短期限、归档、解绑无法立即作用于长期离线电脑。解绑后旧电脑可能继续离线使用，新电脑也可激活，因此不能承诺任何情况下全球同时只有一台使用。
- 机器指纹和本地程序可被篡改或复制，不能承诺不可破解、绝对防复制或绝对防系统时间回拨。

## 3. 组件与部署选择

采用独立 Python FastAPI 授权服务，服务端同时提供轻量模板管理页面及少量原生 JavaScript，不引入大型前端工程。数据库使用授权服务专属 SQLite 持久化文件，单服务进程；不复用博客 MySQL/Redis。数据访问、签名、授权规则、管理员会话和页面路由分模块。

授权服务部署在新 Docker 容器中，使用非 root 用户，只通过内部 Docker 网络接受现有 Nginx 转发，不公开数据库或授权后端端口。SQLite、签名密钥与必要配置持久化并分离权限。

复用 blog-frontend Nginx，新增精确 server_name license.txblog.cn 的独立配置，保留博客原有 server 块和路由。为该域名配置 TLS、80 到 HTTPS 的域名限定跳转与证书自动续期；不将全站 HTTP 重定向规则套用到博客。

部署前只读确认现有 Compose 文件位置、容器挂载、Docker 网络、Nginx 配置、443 占用和云防火墙。所有变更先备份，Nginx 配置验证通过才加载。添加 443 映射如需重建博客前端容器，应提前说明短暂中断并由用户选择部署时机，不擅自停止博客。实际部署路径和证书验证方式依据上述现场检查写入部署步骤；不猜测生产文件路径。

## 4. 管理员安全与管理界面

管理员由服务器初始化命令创建，密码交互输入，不出现在命令参数、镜像、源码、日志或聊天中。保存 Argon2id 密码哈希，不保存明文。忘记密码通过服务器命令重设并撤销全部管理会话。

管理会话保存在服务端，浏览器使用 Secure、HttpOnly、SameSite Cookie；默认 30 分钟不活动过期、8 小时绝对过期，登录后轮换会话。修改操作使用 CSRF 防护、同源检查和 POST/其他明确写入方法；退出撤销会话。管理 API 全部检查身份。登录限流按账户与客户端来源组合实施，不永久锁死管理员。仅信任已配置 Nginx 的转发头。

界面为简洁中文桌面优先页面：登录、卡密列表、生成卡密、编辑详情和审计记录。支持分页，按状态、备注、编号搜索及按到期时间筛选。敏感操作有明确确认，错误不暴露堆栈或密钥。

管理功能：

- 单个或批量生成随机高熵联网卡密，设置正整数有效天数或永久，填写备注。天卡/月卡/年卡作为可编辑天数预设，月卡默认 30 天、年卡默认 365 天，不使用模糊自然月换算。
- 限时卡从第一次成功激活按服务器 UTC 时间开始计时；界面显示香港时间。未激活时可改有效天数，已激活时可编辑明确到期时间或改永久。
- 续期以当前有效到期时间与服务器当前时间两者的较晚值为起点增加天数；永久卡不叠加天数，改限时需明确设置日期。
- 停用、恢复、解绑、备注编辑。解绑保留原激活时间及到期时间，不重置剩余期限，递增绑定版本。
- 删除为停用并归档，不物理删除。默认列表隐藏归档记录，审计保留且可查询；不提供清空审计功能。
- 展示卡密编号、掩码、状态、绑定设备摘要、首次激活时间、到期时间、最近成功校验时间；最近校验不能被描述为实时在线。
- 完整卡密仅生成时展示，并允许该次下载批次文件。网站后续不支持找回明文；未保存时需停用并重新生成。一次展示不是防泄露保证。

卡密摘要使用服务端秘密参与的 HMAC-SHA256；秘密与数据库分开保存。签名私钥与摘要秘密都不进 EXE。审计记录操作类型、管理员、卡密编号、时间及非敏感变更，不记录完整卡密、密码或会话令牌。

## 5. 联网激活与协议

客户端机器指纹沿用现有 MachineGuid 派生方式，避免无必要更换指纹。软件提供明确的联网/旧版离线入口；联网卡密带区别于旧版的格式前缀。

首次激活提交卡密、机器指纹、客户端版本和随机请求 nonce；不发送收货地址、订单、浏览器 cookie 或抖音账号。服务端在单个数据库事务内检查卡密状态及绑定：未绑定则绑定当前设备并启动期限；同设备则幂等返回；其他设备拒绝。激活与停用、解绑的并发写入也使用事务，避免读写竞争。

成功响应返回 Ed25519 签名授权凭证，固定版本化格式，包含产品标识、卡密 ID、机器指纹、绑定版本、签发时间、期限类型、到期时间与签名 key ID；签名覆盖全部字段。EXE 只包含受信任公钥；严格验证产品、签名、设备和期限，不接受响应提供的任意公钥。永久卡无到期时间，限时卡必有到期时间。

后续校验使用本机持有的签名凭证和 nonce，不要求保存卡密明文。服务端核对当前状态和绑定版本；响应绑定本次 nonce，并对授权结果及拒绝结果签名。伪造、过期请求响应或错误签名不能更新本地状态。

明确拒绝包括停用、归档、过期或绑定不匹配；本机记录最近有效的拒绝状态，断网不得将已收到的拒绝降级成可使用。管理员恢复后需成功联网校验才能恢复。网络超时、5xx、TLS/签名失败属于无法确认，不使用错误响应授予新权限；已有有效凭证按断网规则处理并提示失败原因。

## 6. 客户端状态与任务边界

联网凭证与旧版 license.json 分开存储，不覆盖或迁移旧版有效记录；写入采用原子替换。复制联网凭证到正常的其他机器应因指纹不符拒绝。先严格区分选定授权模式，再决定是否允许开始任务。

首次联网激活必须服务器成功确认。后续启动先本地检查签名、机器、期限及已知拒绝状态，同时异步校验；成功联网后每 10 分钟后台校验，失败按退避重试，避免刷屏。设置网络请求超时，Tk 主线程不得被网络请求阻塞。点击任务开始只读取本地授权状态并触发后台检查，不能同步等待远程 API。

后台返回明确拒绝或本地到期后，禁止新任务，现有任务在下一安全检查点停止新增购买动作；不强制关闭浏览器、不取消订单，已提交订单可继续只读确认和人工处理。开售检测到单次点击之间不插入联网请求或文件写入。授权状态与抢单线程通过轻量线程安全快照交互。

本地到期检查结合上次可信服务器时间、持久化已见时间上限和进程内单调时间，明显回拨提示联网确认，不因系统时间回拨延长授权。离线软件无法防住文件回滚、虚拟机快照或破解，界面和文档如实说明。续期、期限变更及解绑只有本机成功重新联网后才获得新状态。

## 7. 数据与运维

专属数据库包括管理员、服务端会话、卡密、激活/校验摘要与审计表。卡密 ID 和摘要有唯一约束，绑定字段、期限和状态有约束。重启后数据保留，迁移具备版本管理；备份使用 SQLite 一致性备份方式，不直接复制正在写入的单一数据库文件。

提供部署文档、初始化管理员与签名密钥命令、密码重设、备份恢复、健康检查和回滚步骤。签名 key ID 为后续轮换预留；更换公钥须先交付支持新公钥的客户端，丢失私钥不得静默生成新钥破坏现有授权。

健康接口只暴露服务可用性，不公开卡密数据。默认关闭公网调试及交互 API 文档，不把签名密钥、用户 IP、完整设备 ID 输出到普通日志。管理页仅展示所需设备摘要。

现有 MySQL/Redis 的全接口端口映射只作为单独风险提示；本项目不擅自修改其防火墙或端口。

## 8. 测试与验收

1. 两台不同指纹并发首次激活同一张卡，仅一台成功；同设备重复激活幂等。
2. 期限首次计时、过期、修改、永久切换、续期和解绑不重置期限；停用/激活并发状态一致。
3. 管理登录、限流、会话过期、退出、密码重设、CSRF、未登录访问、输入注入和日志脱敏测试。
4. 完整卡密仅生成返回，后续列表/日志/数据库不可取得明文；批量生成异常不产生不可追踪半批次。
5. 签名、产品、设备、绑定版本、nonce、格式及期限篡改拒绝；已知拒绝不能通过普通断网恢复。
6. 首次断网无法激活，已有有效凭证可断网使用，到期照常限制；时间回拨、续期尚未联网的提示准确。
7. 旧版离线激活及已有记录兼容，不因授权服务失败改变模式；原秒杀及人工验证回归测试通过。
8. 以本地模拟测试确认远程授权 API 故障不阻塞 GUI 或开售点击链路，并报告测量而非承诺零开销。
9. 管理页面浏览器功能与视觉检查；不进行真实抖音交易测试。
10. 容器重启持久化、备份恢复、TLS 校验和续期流程检查；上线后验证博客原域名及授权域名各自路由。
11. EXE 打包、嵌入源码一致性检查、启动测试及旧版备份，最终更新 dist/DYLiveAssistant/DYLiveAssistant.exe。服务未部署或公钥未配置前不得宣称联网可用。
